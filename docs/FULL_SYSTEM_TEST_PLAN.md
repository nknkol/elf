# 完整形态测试与验收规范

本文定义 ELF/PRoot 文件系统隔离工具最终形态的测试清单，不是现有测试索引，也不表示
其中能力已经实现。所有用例初始状态均为 **NOT_RUN**，不能从现有进度自动继承通过。
当前实现另见 [STATUS.md](STATUS.md)。本文只规定测试，不添加测试程序或修改运行时。

产品的主要用途是在系统沙盒内，为 agent 配置宿主系统/brew 工具、工作区和私有状态的
文件视图；次要用途是运行 Linux rootfs。底层依赖系统沙盒提供其已有的隔离，不要求
ptrace、新 namespace 或额外系统沙盒。文件内容、偏移和普通 IO 继续由内核处理。

## 1. 验收范围与基本契约

### 1.1 两种产品模式

| 模式 | 最终必须验证的能力 | 不应混淆的能力 |
| --- | --- | --- |
| Agent | 默认拒绝未暴露文件；brew/系统依赖只读；工作区可写；独立 home/tmp/cache；后代进程继承策略 | 能启动一个 shell 不代表文件隔离成立 |
| Container | rootfs 路径、libc、进程与文件语义；只读/可写 bind；常见构建、归档、包管理工作流 | rootfs 与路径重映射不等于内核容器或虚拟机 |
| 共同底层 | SVC 控制、路径解析、挂载来源、FD/映射生命周期、可信执行交接、错误恢复 | 进入慢路径不等于 syscall 已实现，也不等于授权正确 |

bubblewrap 仅作为部分文件视图与配置语义的参照，不作为运行依赖。
不承诺 PID/network/user namespace、内核 capabilities、特权 mount 或完整系统启动。
不在范围内的操作必须明确拒绝或声明由系统沙盒处理，不能伪装成已实现。
网络限制若未来加入，需要单独验收；但 socket 携带 FD、路径型 Unix socket 和可修改
文件的设备接口已经属于本文文件边界范围。

### 1.2 文件访问契约

以下是本测试规范采用的目标契约；实现若选择不同的公开语义，应先修订契约和用例，
不能在失败后临时调整预期。支持的 Linux 子集、资源上限及错误码优先级必须版本化。

| 对象/操作 | 目标结果 |
| --- | --- |
| 未暴露或显式 deny 的路径 | 不得读取内容、获取未授权元数据或修改；直接访问统一 EACCES，目录枚举隐藏该项 |
| 为到达已暴露子树而存在的祖先 | 仅提供必需的遍历/合成目录视图；不能借祖先列出宿主其他子项 |
| ro 视图 | 可按配置读取、枚举和执行；修改请求返回 EROFS；允许内核按宿主规则产生读取 atime 等副作用 |
| rw 视图 | 在宿主权限允许时保持已声明的 Linux 语义；配置不能扩大宿主权限 |
| 未知或不可信 FD 来源 | 默认拒绝受控文件操作；只有明确、可验证的能力授予入口可接纳 |
| 同一宿主对象的不同 bind | 权限属于打开时的视图/明确授权能力，不能仅按路径字符串或 dev/inode 合并 |
| 已打开、改名或 unlink 的文件 | 在声明支持的生命周期内保持原能力和内核对象语义；不得误指向同名新对象 |
| 跨虚拟挂载 rename/link | 在两端权限检查之后返回 EXDEV；不能靠复制伪造原子 rename 或硬链接 |
| 不支持或宿主禁止的 syscall | 使用契约规定的 ENOSYS/EOPNOTSUPP/EPERM 等可处理错误；不能因遗漏路由导致宿主 SIGSYS |
| 无法可靠执行策略 | 启动失败或受控终止，不能自动切到未隔离/观察/旧后端模式 |

拒绝优先级另以错误码表固定：无效 FD/用户指针/flags、不可见路径和只读策略同时存在时，
不得用宽泛的“返回任意错误”掩盖结果变化。不能通过错误差异泄露 deny 路径的存在性。
有意隐藏路径若以后采用 ENOENT 契约，应整体替换相关期望，并验证一致性。

### 1.3 对抗模型与可信边界

guest 可以执行自带 AArch64 机器码，构造任意 syscall、参数、信号、线程、子进程和
恶意快照；可以写其获准的文件、匿名内存和共享内存；可以尝试覆盖或跳转到 loader、
payload、元数据、原生 SVC 入口。不能假设 guest 只通过 libc，或仅运行扫描时的代码。

宿主测试控制器、可信启动策略来源和内核是可信的。宿主协作者可在测试中并发改名、
替换路径或修改共享文件，用于验证竞争边界，但不得凭其直接修改 canary 的行为指控
被测程序越权。控制器必须记录每个修改者及操作序列。

若同地址空间的代码/数据保护无法阻止 guest 篡改授权状态，必须记录隔离门槛失败，
只能发布为合作程序兼容工具，不能用“所有 SVC 已扫描”代替证明。时间/缓存等微架构
侧信道、恶意内核和无限资源拒绝服务不纳入本文件隔离保证；可见路径、元数据、FD、
日志和内容通道的信息泄漏属于验收范围。

## 2. 执行方法、环境矩阵与证据

### 2.1 环境矩阵

| 维度 | 必测取值 |
| --- | --- |
| 产品 | agent；container；仅用于回归对照的兼容/旧模式 |
| 用户态 | 静态 AArch64 原始 syscall 探针；musl/Alpine；glibc/Ubuntu；宿主/brew 动态工具 |
| backing | 大小写不敏感 home；大小写敏感临时目录；大小写敏感应用私有持久目录；混合嵌套 backing |
| 访问配置 | deny/ro/rw；未知来源；嵌套 ro→rw、rw→ro、deny→显式暴露；同源多别名 |
| 入口 | 绝对路径；cwd 相对；dirfd 相对；O_PATH；AT_EMPTY_PATH；继承/接收/复制的 FD |
| 进程 | 单进程；fork；vfork；线程；共享 VM/FD 组合；多次 exec；信号中断/重入 |
| 文件对象 | 普通文件；目录；symlink；硬链接（能力允许时）；FIFO/pipe；socket；PTY；设备；memfd |
| 资源 | 空、典型、边界最大、超过上限；短 IO；超长参数；ENOMEM/EMFILE/ENOSPC；部分初始化失败 |
| 宿主 | 每个声明支持的 OS/内核/应用沙盒身份；固定身份重复测；系统更新后重新测 |

在三个 backing 内创建专用随机测试子目录，不对真实 home、brew 安装或用户项目做破坏性测试。
应用私有路径随应用身份改变，测试报告必须记录身份，不能只记录相同的路径文本。
ASCII 大小写、Unicode 折叠和 Unicode 规范化必须分别探测，不能相互推断。

正交组合使用成对覆盖控制规模；涉及权限升级的组合必须全覆盖：权限 × 路径入口 ×
对象别名、权限 × FD 获取方式 × fork/exec、权限 × 写入通道、可执行内存 × 写入别名。
不适用的组合要记录原因，不能无记录地省略。

### 2.2 用例记录与结果分类

每条用例至少记录：ID/版本、优先级、模式、环境、配置摘要、fixture、前置条件、步骤、
准确的返回值/errno/信号/输出、宿主后置状态、资源回收、执行时间、证据路径和结论。
参数化子用例用 `ID/variant` 命名，不能一个 ID 只跑正向例便全部标记通过。

| 结果 | 含义 |
| --- | --- |
| PASS | 所有预期与证据完整满足 |
| FAIL | 行为错误、越权、非预期信号、状态损坏、泄漏或超时 |
| BLOCKED | 环境、契约或必需依赖缺失，无法验证 |
| SKIP | 该发布范围明确不适用，附可核查理由 |
| XFAIL | 已知缺陷已复现，有问题编号和预期失败点，仍不算通过 |
| NOT_RUN | 尚未执行，无成功含义 |

优先级：**P0** 为隔离/数据完整性/启动可信链阻断项；**P1** 为完整产品必需的兼容和
生命周期能力；**P2** 为扩展平台、长时间稳定性及优化。相关范围一旦公开支持，其 P2
测试也成为该范围发布门槛。安全门槛内的 SKIP/BLOCKED/XFAIL 均不能作为通过。

### 2.3 判定方法

1. 使用三方核对：guest 可见结果、独立宿主观察、预先定义的契约/参考行为。
2. 宿主预置不同内容的 rw/ro/deny canary，记录字节、大小、mode、owner、xattr、
   链接数、目录项和相关时间戳。拒绝后核对内容与结构；区分允许的 atime 变化。
3. 内容泄漏测试使用控制器生成、guest 不预先知道的随机 token；检查 stdout、stderr、
   IPC、可写文件和诊断输出。用已知常量“证明读到秘密”无效。
4. 原生对照用于确认本机能力；标准 Linux 对照用于确认目标语义。两者不一致时分别
   记录“宿主偏差”和“后端偏差”，不能以本机也错为 Linux 兼容通过。
5. 拒绝用例检查宿主无残留副作用；成功用例检查实际字节/对象/偏移/链接关系。
   子进程退出 0、函数被调用、元数据表匹配都不是单独充分证据。
6. 竞争用例同时使用可控握手和持续随机调度，保存 seed、操作日志、失败最小重现。
   多次没有复现不是竞态不存在的证明，还需检查实现的原子性依据。
7. 每个测试有进程组级超时、后代回收、临时目录清理和泄漏检查；失败清理不能触碰
   测试目录之外的路径。故障日志仅按测试 PID/时间/应用身份匹配，不能清空系统日志。

## 3. 配置、启动与宿主空间（CFG）

| ID | 级别 | 场景 | 预期/验收证据 |
| --- | --- | --- | --- |
| CFG-01 | P0 | 空、截断、重复键、未知字段、错误类型、非法版本的配置 | 拒绝启动；不执行 guest，不留下半初始化 state |
| CFG-02 | P0 | 缺省权限、遗漏 root、空 mounts、未配置宿主路径 | 默认拒绝，不回退为宿主全盘可见 |
| CFG-03 | P0 | CLI、配置、环境变量的冲突与覆盖 | 明确且固定的优先级；guest 不能通过参数或环境撤销策略 |
| CFG-04 | P0 | state 位于暴露树内、symlink/大小写/祖先/同源别名重叠 | 启动前拒绝；未创建的尾路径和并发替换也不能绕过 |
| CFG-05 | P0 | guest 修改配置、策略数组、mount ID、内部状态目录 | 不改变正在执行的授权；不得读取认证材料或内部传输内容 |
| CFG-06 | P1 | 私有 home/tmp/cache、cwd、umask、环境白名单 | 位置/权限正确；双实例状态独立；宿主 HOME 与凭据默认不继承 |
| CFG-07 | P1 | brew 前缀、Cellar/opt symlink、系统动态库和资源显式暴露 | 实际工具可运行；只读依赖不可修改；外部依赖缺失有准确诊断 |
| CFG-08 | P1 | 路径包含空格、换行、冒号、非 ASCII、shell 元字符 | 精确传递，无 shell 展开/命令注入；不支持的表示明确拒绝 |
| CFG-09 | P0 | loader/payload/配置 ABI 错配、旧版本、损坏产物 | guest 执行前拒绝；不存在兼容降级绕过 |
| CFG-10 | P1 | 启动中断、并发启动、同名 state、残留旧实例 | 独占创建、正确所有权；不删其他实例数据；可重复恢复 |
| CFG-11 | P0 | 观察模式/调试参数/自定义 payload 被 guest 再执行 | 不能脱离既有策略；诊断开关不能变成提权入口 |
| CFG-12 | P1 | 支持的 bubblewrap 风格路径配置、重复目的路径与顺序 | 行为有明确映射；不支持的 namespace/权限参数启动即拒绝 |

## 4. 路径、挂载视图与可见性（PATH）

以下各项至少覆盖 deny/ro/rw、绝对/cwd/dirfd 入口，以及边界内外不同内容的 canary。

| ID | 级别 | 场景 | 预期/验收证据 |
| --- | --- | --- | --- |
| PATH-01 | P0 | `.`, `..`, 连续斜杠、根目录、空路径、尾斜杠 | 不越根；文件/目录判定、ENOENT/ENOTDIR/空路径规则准确 |
| PATH-02 | P0 | 最长组件前缀；`/work` 与 `/workspace`；重复/嵌套 bind | 仅匹配完整组件；选中正确视图与权限 |
| PATH-03 | P0 | ro 父/rw 子、rw 父/ro 子、deny 父/显式子树 | 子树权限准确；祖先不暴露未授权兄弟和宿主元数据 |
| PATH-04 | P0 | 绝对/相对 symlink、跨挂载链接、链/环/断链 | 按 syscall 的 follow 语义解析，检查最终对象；ELOOP 有界 |
| PATH-05 | P0 | 同源多个 bind、不同权限、不同嵌套遮盖 | 路径相同或 inode 相同不合并权限；每个入口得到各自内容视图 |
| PATH-06 | P0 | cwd/dirfd 下访问 `..`、切换到嵌套 bind 后返回 | 正确处理挂载边界，不能反向映射到更宽权限入口 |
| PATH-07 | P1 | chdir/fchdir/getcwd；cwd 被改名/unlink；路径缓冲不足 | 按声明语义返回实际 guest 位置或准确错误，不泄露宿主 backing |
| PATH-08 | P0 | 已打开 dirfd 被改名、移入遮盖树、移出可见树 | 不重定位到同名其他目录，不扩大能力；支持语义与保守拒绝分别记录 |
| PATH-09 | P0 | getdents64/readdir、seekdir/telldir、分页和 rewind | deny 项隐藏；挂载子项出现且无重复；不泄露宿主未暴露名字 |
| PATH-10 | P0 | stat/lstat/fstatat/statx、access/faccessat、readlink | 内容权限与元数据/存在性策略一致；只读路径不能报告可写成功 |
| PATH-11 | P1 | PATH_MAX/NAME_MAX 边界、超长 symlink、深层目录 | 正确失败，无越界、截断访问另一对象或无限循环 |
| PATH-12 | P0 | openat2 全部声明支持的 RESOLVE_* 与组合 | BENEATH/IN_ROOT/NO_SYMLINKS/NO_MAGICLINKS/NO_XDEV/CACHED 各自严格成立；不能忽略 flags |
| PATH-13 | P0 | openat2 how 大小、未知 flags、尾部非零、dirfd 无效 | 兼容明确 ABI 子集；不支持时拒绝，不退回无约束 open |
| PATH-14 | P0 | `/proc/self/root`、`cwd`、`fd/N` 等 magic link 别名 | 不能绕过 root/挂载/权限来源；打开后仍检查正确来源 |
| PATH-15 | P0 | deny 对象存在/不存在的错误、输出、目录项对照 | 按契约隐藏，不通过可见错误字段泄露对象信息 |
| PATH-16 | P1 | statfs/fstatfs、挂载信息、只读标记与容量信息 | 与公开文件视图一致；不声称拥有不存在的虚拟文件系统能力 |

| ID | 级别 | 场景 | 预期/验收证据 |
| --- | --- | --- | --- |
| STORE-01 | P1 | 每种 backing 原生 case/hardlink/权限探测 | 独占 scratch；区分 denied/unsupported/unknown；无残留，无隐式授权 |

| STORE-05 | P0 | 混合 backing 的嵌套挂载、不同拼写 state 路径 | 每个实际 backing 分别处理；隐藏 state 无别名入口 |
| STORE-06 | P1 | 宿主拒绝 link/linkat，含 AT_EMPTY_PATH | 返回准确错误；无复制/软链接替代，无目标残留 |

| STORE-08 | P0 | 同一 inode 的 ro/rw/deny 硬链接或 bind 别名 | 从 ro/deny 获得的能力不能升级；rw 修改可被 ro 读到不算 ro 写绕过 |
| STORE-09 | P1 | 解包中 `A`/`a` 冲突、大小写专有 rename | 不静默覆盖；Linux rootfs 选择敏感 backing，或显式拒绝不兼容镜像 |
| STORE-10 | P1 | 显式归档硬链接复制兼容模式 | 默认关闭；报告降级；副本独立，不作为运行时 link 语义通过 |
| STORE-11 | P0 | 宿主其他应用/不同启动身份的相同私有路径文本 | 不缓存上一身份的能力/权限结果，不暴露另一实例数据 |
| STORE-12 | P1 | backing 配额满、只读、被移走、权限变化、I/O 错误 | 不改投其他可写目录；错误和残留可核查，清理只处理所属对象 |

## 6. 文件操作、元数据与数据通道（FILE）

每个修改入口必须有 rw 成功、ro 拒绝、deny 拒绝、未知来源拒绝四类；每个读取入口
必须验证 deny 无内容泄漏。修改拒绝同时检查宿主实际状态，不仅检查 errno。

| ID | 级别 | 场景 | 预期/验收证据 |
| --- | --- | --- | --- |
| FILE-01 | P0 | open/openat/openat2 的访问模式、CREATE/EXCL/TRUNC/APPEND/TMPFILE/PATH/NOFOLLOW | 准确区分读、写、创建和路径句柄；检查前不得 truncate/create |
| FILE-02 | P0 | read/pread/readv/preadv/preadv2；EOF、偏移和短读 | deny 不可读；可读文件的内容、偏移和短读与内核一致 |
| FILE-03 | P0 | write/pwrite/writev/pwritev/pwritev2；append、短写 | 所有入口执行同一权限；拒绝无部分写入；已授权短写报告真实长度 |
| FILE-04 | P0 | truncate/ftruncate/fallocate 的 punch/zero/collapse/insert 等 flags | 所有修改变体受控；稀疏区、大小和数据正确；未知 flags 不直接透传 |

## 10. 系统调用全量分类与 SIGSYS（SYS）

“全量”指每个发布目标使用的 AArch64 syscall 编号表及所有入口，而不是某个固定数量。
发布时固定内核 UAPI/头文件版本，列出命名 syscall、保留空洞、私有入口和未知编号策略。
每个 syscall 台账包含：编号/名称、参数 ABI、文件影响、支持子集、宿主实测、路由、授权点、
失败语义、实际探针 ID、风险和声明。进入慢路径的数量不能充当功能完成率。

| ID | 级别 | 场景 | 预期/验收证据 |
| --- | --- | --- | --- |
| SYS-01 | P0 | 编号表与分发代码/测试台账双向核对 | 每项标为支持、受控拒绝或已审计直通；无遗漏/重复/编号名称错配 |
| SYS-02 | P0 | 原生宿主探测与后端探测，同参数配方 | 分别记录返回值、errno、信号、超时；原生 SIGSYS 项后端不能再被误放行 |
| SYS-03 | P0 | unshare/mount/chroot/setns/pivot_root 等敏感入口 | 编号从目标 ABI 核对；受控拒绝且 guest 能继续执行后续标记 |
| SYS-04 | P0 | 普通快速 syscall 的分类 | 证明不携带路径/FD/VM/执行状态绕过；不为图方便把所有 syscall 都转慢路径 |
| SYS-05 | P0 | 按参数触发的宿主过滤、不同 flags/对象/权限 | 一个参数返回成功不算整个 syscall 安全；合法/非法/边界配方分别测试 |
| SYS-06 | P0 | 未知编号、保留编号、高位值、未来新增调用 | 默认安全拒绝，不能未经审计直接 SVC |
| SYS-07 | P1 | 原始 syscall 与 musl/glibc wrapper/fallback 对照 | 不依赖 libc 恰好回退掩盖漏拦截；ENOSYS 回退结果仍受策略控制 |
| SYS-08 | P0 | 用户指针 NULL/未映射/跨页/并发变更，嵌套结构和长度 | 不崩溃控制器、不越界读写；实际使用参数与检查参数一致 |
| SYS-09 | P1 | 返回寄存器、SP、callee-saved、TLS、错误号、clone 双返回 | 与 ABI 一致，正常程序无隐性寄存器破坏 |
| SYS-10 | P0 | OS/系统沙盒升级、不同应用身份后重新扫描 | 能力画像失配不能静默沿用；新增 SIGSYS 风险阻断发布 |

原生危险探针仅在可回收的独立子进程和自有 fixture 内运行；不能向真实 mount、设备、
进程或用户文件发起破坏性调用。无法安全构造的配方标记 BLOCKED 并补审计，不能假装
执行成功。需 SIGSYS 的探针与预期不出现信号的产品测试分别汇总。

| AGENT-06 | P1 | pip/npm 等本地缓存与依赖安装、离线/受控在线场景 | 写入私有 cache/workspace；不能修改只读 brew 或宿主全局环境 |

| AGENT-08 | P0 | agent 生成并执行绕过程序、再次启动 loader、恶意脚本 | 与原始 syscall 对抗测试具有相同边界，不因“工具调用”而豁免 |
| AGENT-09 | P1 | 两个 agent 并行、取消一个、恢复另一个、重复会话 | 私有状态和能力隔离；持久化仅按配置发生 |
| AGENT-10 | P1 | 缺依赖、只读写失败、资源满、无网络 | 可理解的诊断和准确退出码；不能自动扩大 mounts 或回退未隔离执行 |

## 14. Linux rootfs、归档与包管理（CTR）

Alpine/musl 与 Ubuntu/glibc 分别执行全部适用项；镜像、包和工具版本记录摘要，不绑定
某个历史镜像版本。涉及 hardlink 的 fixture 必须区分原生支持与显式复制降级。

| ID | 级别 | 场景 | 预期/验收证据 |
| --- | --- | --- | --- |
| CTR-01 | P1 | 静态/动态程序、shell、ld.so、TLS、auxv、locale、时区 | 正确启动和输出；不偷用宿主同名库使测试假通过 |
| CTR-02 | P1 | ls/find/cp/mv/rm/mkdir/chmod/stat/readlink、相对/绝对路径 | 内容、目录与元数据正确；两 libc 独立通过 |
| CTR-03 | P1 | tar 打包：相对/绝对源、`-C`、嵌套目录、排除项 | 检查成员名/类型/内容/链接目标；不能仅判断 tar 返回 0 |
| CTR-04 | P1 | tar 解包：嵌套、覆盖、目录属性、symlink、时间戳 | 与 fixture 清单逐项比对；拒绝不支持特性并报告部分状态 |
| CTR-05 | P0 | 恶意归档：`..`、绝对路径、symlink/hardlink 穿越、顺序替换 | 在策略边界外不能落盘；安全解包入口还应拒绝逃出指定解包目录 |
| CTR-06 | P1 | 硬链接打包/解包、先后目标、断目标、循环目标 | 验证真正链接关系；受限 backing 明确失败/显式降级，不静默假成功 |
| CTR-07 | P1 | gzip/xz/bzip2/zstd、稀疏文件、长名、非 ASCII、空文件 | 打包→解包内容及允许元数据一致；依赖缺失记 BLOCKED |
| CTR-08 | P1 | apt/dpkg 与 apk 的本地安装/升级/移除、维护脚本 | 文件数据库与实际结果一致；链接/owner/权限限制准确报告，不伪造成功 |
| CTR-09 | P1 | 受控仓库联网安装、DNS/证书/时间资源 | 网络由宿主现有能力提供；下载验证和安装完成，外部服务失败单列 |
| CTR-10 | P1 | 编译链接运行、小型构建系统与测试套件 | 依赖/进程/临时文件完整工作，无 fixture 特判 |
| CTR-11 | P0 | guest root 身份展示与实际 chown/setuid/mount 请求 | 虚拟展示不能变成宿主权限；不支持特权操作明确失败 |
| CTR-12 | P1 | 只读 rootfs + 可写 work/tmp/home、持久 rootfs 重启 | rootfs 不被改写；持久目录保存、临时目录清理符合配置 |
| CTR-13 | P1 | pty 交互 shell、作业控制、信号、管道、退出 | 输出/终端状态正常，子进程回收，终端不留损坏模式 |

## 15. 性能与长期稳定性（PERF）

性能门槛不能以安全检查关闭为代价。以下为初始验收预算建议，首次正式基线建立后由
发布契约固定；若修改，必须保留旧值、测量证据和理由，不能为消除失败悄悄抬高预算。
所有性能结果同时注明权限模式、trace 是否开启、温度/负载、缓存状态和 backing。

| ID | 级别 | 场景 | 指标与目标 |
| --- | --- | --- | --- |
| PERF-01 | P1 | 纯 read/write/pread/pwrite 顺序及随机 IO | 对照原生吞吐与延迟；不逐次路径解析，不复制完整内容到用户态 VFS |
| PERF-02 | P1 | open/stat/目录遍历；深路径、多 bind、symlink | p50/p95/p99、syscall 次数、分配数；无随历史操作无限增长的扫描 |
| PERF-03 | P1 | loader 冷/热启动、fork/exec 链、不同继承 FD 数量 | 启动耗时及恢复成本单列；不得把 exec 的身份检查隐藏在普通 IO 指标中 |
| PERF-04 | P1 | 映射/修改保护、JIT、共享映射写回 | 检查开销与真实工作负载影响；不通过漏扫或 RWX 透传优化 |
| PERF-05 | P1 | agent 搜索/构建/测试、容器解包/打包 | 对照同 backing 原生/兼容后端/受保护模式，报告总耗时和峰值 RSS |
| PERF-06 | P2 | 长时间混合 IO/fork/exec/信号/FD 传递 | 至少 8 小时 soak；FD/RSS/任务/临时文件无持续净增长 |
| PERF-07 | P1 | 容量上限附近、并发竞争、信号密集 | p99 和超时计数受控，无忙等耗尽 CPU 或指数级退化 |

建议首版量化预算：大型顺序 IO 吞吐不低于同 backing 原生的 90%；代表性文件工作流
总耗时不超过原生的 2 倍；启动和 exec 另建立绝对预算，不用对极短程序的比例下结论。
每项至少 5 次预热、30 次有效采样；低时长项目批量计时，报告离散程度及置信区间。
若宿主噪声过大，则 BLOCKED 重测，不取最快一次。上述预算不表示当前实现已达成。

## 17. 最终验收套件与发布门槛

### 17.1 分层执行

| 套件 | 内容 | 用途 |
| --- | --- | --- |
| T0 契约与静态核对 | 配置 schema、ABI、syscall 台账、能力/限制表、拒绝入口审计 | 发现遗漏和未经定义的行为 |
| T1 核心模型 | 挂载选择、权限、FD/任务/映射状态机、快照解析、容量/错误原子性 | 可穷举的小状态与属性验证 |
| T2 真实 syscall | 原始 SVC + 宿主后置检查 + 原生/标准 Linux 对照 | 验证模型真正接入运行时 |
| T3 生命周期与对抗 | 竞争、信号、代码改写、伪造交接、导入 FD、故障注入 | 验证不可绕过与失败安全性 |
| T4 产品工作流 | agent/brew、musl/glibc rootfs、归档、包管理、并行构建 | 验证完整使用方式 |
| T5 环境与稳定性 | backing/宿主矩阵、性能、soak、系统更新重测 | 验证可交付范围 |

核心模型 PASS 不能代替 T2/T3；兼容模式 PASS 不能代替受保护模式；musl PASS 不能
代替 glibc。当前实验构建的资源上限、保守拒绝和支持子集不得直接定义“完全体已完成”。

### 17.2 发布结论

- **可运行兼容工具**：允许部分隔离项未完成，但名称、帮助和文档必须明确不提供恶意
  guest 文件隔离。不得把此结论写成“安全容器”。
- **Agent 文件隔离可发布**：该发布环境所有相关 P0、AGENT 必需 P1 和共同底层 P1
  通过；默认拒绝读取、所有修改通道、执行可信链、动态代码控制和竞争边界无已知缺口。
- **Container 模式完整验收**：在上述共同底层之上，CTR 必需项在 musl/glibc 分别通过；
  不支持的内核特权能力明示，不把显式硬链接复制降级称为 Linux 链接语义实现。
- **完整形态验收**：两种产品模式及所有声明支持环境通过，性能预算固定并达成，发布
  阻断项没有 SKIP/BLOCKED/XFAIL，未解决契约问题不得留为“以后再说”。

只统计适用范围内的 **PASS / 必需子用例总数**，同时分别列出 FAIL、BLOCKED、SKIP、
XFAIL 和 NOT_RUN。安全门槛是全部满足的条件，不取平均；即使兼容性 99% 通过，一项
可读取 deny 文件或改写可信控制面的漏洞也使隔离验收失败。

### 17.3 执行前需要固定的设计决定

这些是测试必须暴露的决策，不是本文件替实现作出的功能承诺。未定时相关用例 BLOCKED。

1. 可信启动/exec 交接和同地址空间控制数据的保护依据；不能只依赖封印 memfd。
2. 完整路径操作的竞争防护机制，尤其是缺少可用 openat2 能力的宿主环境。
3. 线程/clone 的最终支持组合与宿主偏差处置；明确是否满足真实 agent 必需的并发。
4. 已打开并被改名/unlink 的对象、同源多视图和跨 exec 来源的稳定能力语义。
5. proc 合成/过滤范围、目录祖先展示、FD 接纳规则和系统资源白名单。
6. 硬链接、大小写冲突、xattr/ACL、设备/ioctl、异步 IO 的支持/拒绝矩阵。
7. 可执行代码/JIT/共享 RX backing 的可支持范围，以及扫描后写入的防护依据。
8. 错误码优先级、资源上限、性能预算、取消/清理和持久 state 的产品契约。

### 17.4 最终报告模板

每次正式验收生成独立报告，至少包含：

- commit、分支、构建摘要、payload ABI、配置/fixture/镜像摘要、宿主与应用身份。
- 发布模式与能力契约版本；测试矩阵的已覆盖和未覆盖组合。
- 每个 ID/variant 的结果、精确预期/实际、宿主后置状态和证据链接。
- syscall 台账与原生扫描差异；原生宿主偏差、后端缺陷、环境故障分别计数。
- 竞争/模糊测试 seed、次数、持续时间、故障最小样本及安全审计依据。
- 性能分布、原生基线、资源上限、长时间泄漏曲线和失败清理结果。
- 未通过项及其发布影响，明确给出兼容、agent 隔离、container 三个独立结论。

报告只能陈述实际完成的验证。本文是一份目标测试规范，文档完成不构成任何运行时
能力、安全保证或测试通过声明。
